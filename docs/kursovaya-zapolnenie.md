## Определения, обобщения и сокращения

**Браузер** — программное обеспечение для просмотра веб-страниц и взаимодействия с веб-приложением по протоколу HTTP/HTTPS.

**Фреймворк** — программная платформа, задающая структуру приложения и предоставляющая готовые компоненты. В серверной части используется фреймворк NestJS (Node.js, TypeScript).

**Веб-приложение** — клиент-серверная система, доступная через браузер без установки отдельного клиента на устройство пользователя.

**REST API** — программный интерфейс, построенный на архитектурном стиле REST; обмен данными в формате JSON по HTTP-методам GET, POST, PATCH, DELETE.

**GraphQL** — язык запросов и среда выполнения для API; клиент запрашивает только нужные поля сущностей.

**JWT (JSON Web Token)** — стандарт представления утверждений между сторонами; в проекте используется для аутентификации после входа по email и паролю.

**Prisma** — ORM для TypeScript/Node.js: описание схемы данных, миграции и типобезопасный клиент к PostgreSQL.

**СУБД PostgreSQL** — реляционная система управления базами данных, в которой хранятся сущности музея и учётные записи пользователей.

**Роль «пользователь» (USER)** — зарегистрированный посетитель, который может просматривать публичные разделы и выполнять операции, отмеченные декоратором `@RequireJwt()` (например, создание экспоната через веб-форму).

**Роль «администратор» (ADMIN)** — пользователь с полным доступом к изменению и удалению контента через REST API и служебные операции (категории, новости, отзывы, посетители, загрузка обложек экспонатов).

**Экспонат** — объект экспозиции виртуального музея (название, описание, категория, обложка, связанные новости и отзывы).

**Посетитель (Visitor)** — профиль гостя музея в предметной области; может оставлять отзывы к экспонатам (отдельно от учётной записи User для входа в систему).

**OpenAPI (OAS) 3.0** — спецификация описания HTTP API; в проекте документация генерируется автоматически (Swagger UI).

**SSE (Server-Sent Events)** — механизм односторонней передачи событий от сервера к браузеру в режиме реального времени (использован в одном из модулей по заданию лабораторной работы).

**ИС** — информационная система «Виртуальный музей технологий будущего».

## Описание предметной области

Предметная область — деятельность **виртуального музея технологий будущего**: хранение и представление информации об экспонатах (квантовые компьютеры, космический лифт, AR-инсталляции и др.), публикация новостей музея, сбор отзывов посетителей, группировка экспонатов по тематическим категориям.

Музей не является физическим учреждением с кассой: пользователи взаимодействуют с контентом через веб-интерфейс с любого устройства. Администраторы и авторизованные пользователи управляют каталогом экспонатов, новостями и отзывами; гости без входа просматривают открытые страницы и каталог.

Основные участники процесса:

- **Гость** — просматривает главную страницу, каталог экспонатов, новости, отзывы, галерею, контакты;
- **Зарегистрированный пользователь** — после входа получает доступ к ограниченному набору операций (создание и редактирование контента через серверные формы);
- **Администратор** — полное управление данными через REST API и административные сценарии.

Доменные сущности: **Category**, **Exhibit**, **News**, **Review**, **Visitor**, а также **User** для аутентификации (роли USER и ADMIN).

## Описание прикладного процесса

Разрабатываемое веб-приложение — **информационная система управления контентом виртуального музея**. Она позволяет сотрудникам и авторизованным пользователям без отдельной разработки страниц добавлять и изменять экспонаты, новости и отзывы, а посетителям — знакомиться с экспозицией и оставлять обратную связь.

Типовые сценарии:

1. **Просмотр экспозиции** — гость открывает список экспонатов, переходит к карточке экспоната, читает связанные новости и отзывы.
2. **Публикация новости** — администратор создаёт новость, при необходимости привязывает её к экспонату.
3. **Модерация каталога** — администратор ведёт справочник категорий, создаёт и редактирует экспонаты, загружает обложку в объектное хранилище.
4. **Работа с отзывами** — фиксируется посетитель (Visitor), оценка и текст отзыва привязываются к экспонату.
5. **Вход в систему** — пользователь регистрируется или входит по email и паролю; сервер выдаёт JWT (cookie `access_token` или заголовок `Authorization: Bearer`).
6. **Интеграция по API** — внешний клиент или фронтенд обращается к REST (`/api/...`) или GraphQL (`/graphql`) согласно документации OpenAPI.

Клиентская часть представлена статическими HTML-страницами (макет музея) и серверными шаблонами Handlebars для CRUD-разделов, смонтированных на NestJS.

## Формирование требований

### Функциональные требования

**Модуль «Категории» (`/api/categories`):**

- получение списка категорий с пагинацией (`page`, `limit`);
- получение одной категории по идентификатору;
- получение экспонатов внутри категории;
- создание, изменение и удаление категории (только роль ADMIN).

**Модуль «Экспонаты» (`/api/exhibits`, страницы `/exhibits`):**

- просмотр списка и карточки экспоната;
- фильтрация/пагинация списка;
- вложенные ресурсы: новости и отзывы экспоната;
- создание, изменение, удаление (REST — ADMIN; веб-формы создания — авторизованный пользователь);
- загрузка обложки экспоната в S3-совместимое хранилище (ADMIN).

**Модуль «Новости» (`/api/news`, `/news`):**

- просмотр списка и детальной страницы;
- создание, редактирование, удаление (API — ADMIN; MVC-формы — по правилам guard).

**Модуль «Отзывы» (`/api/reviews`, `/reviews`):**

- просмотр списка и отзыва;
- создание, изменение, удаление с привязкой к экспонату и посетителю.

**Модуль «Посетители» (`/api/visitors`):**

- CRUD для сущности Visitor;
- просмотр отзывов посетителя.

**Модуль «Аутентификация» (`/auth`):**

- регистрация (`POST /auth/register`);
- вход (`POST /auth/login`, форма `POST /auth/login/form`);
- выход (`POST /auth/logout`);
- страница входа (`GET /auth/login`);
- разграничение доступа: `@Public()`, `@RequireJwt()`, `@RequireAdmin()`.

**Модуль GraphQL (`/graphql`):**

- запросы и мутации по сущностям домена (code-first, песочница Apollo).

**Общие страницы (`AppController`):**

- главная, о музее, галерея, контакты, обратная связь.

### Нефункциональные требования

- Доступ к изменению данных — только после **аутентификации**; критичные операции API — только для **администратора**.
- Описание REST API по **OpenAPI 3.0** (Swagger UI: `/api/docs`).
- Поддержка **CORS** для запросов с разрешённых origin с передачей cookie/заголовка Authorization.
- Хранение данных в **PostgreSQL**; миграции через **Prisma Migrate**.
- Пагинация коллекций с заголовком **Link**; кэширование и **ETag** для GET-запросов API.
- Валидация входных DTO через **ValidationPipe** (class-validator).
- Развёртывание серверной части на **Render.com**; исходный код — **Git** / **GitHub**.
- Загрузка файлов — **Yandex Object Storage** (S3 API).

## Проектирование

### Используемый стек технологий

Решение о разработке **веб-приложения** принято для обеспечения доступа к системе с любого устройства в любое время без установки клиента и с централизованным обновлением на сервере.

| Уровень | Технологии |
|--------|------------|
| Клиент (публичный сайт) | HTML5, CSS3, JavaScript (ES-модули), Particles.js, OpenLayers |
| Клиент (админ/MVC) | Handlebars (hbs), формы POST |
| Сервер | Node.js ≥ 22, **NestJS 11**, **TypeScript**, Express |
| API | REST (JSON), **GraphQL** (Apollo), **Swagger** |
| БД | **PostgreSQL**, **Prisma ORM** |
| Аутентификация | **JWT**, Passport, bcrypt |
| Файлы | AWS SDK → Yandex Object Storage |
| Кэш | @nestjs/cache-manager |
| Версии | **Git**, хостинг **Render.com** |

В качестве HTTP-сервера используется встроенный в NestJS адаптер **Express**. Для работы с БД выбрана **Prisma** как типобезопасный ORM с декларативной схемой и миграциями.

## Разработка

### Реализация серверного API

В качестве описания программного интерфейса использован инструмент **Swagger** (стандарт **OAS 3.0**). Документация формируется автоматически по декораторам `@ApiTags`, `@ApiOperation`, `@ApiBearerAuth` в контроллерах `*-api.controller.ts`.

После запуска сервера (`npm run start:dev` в каталоге `backend/server`) документация доступна по адресу:

`http://localhost:3000/api/docs`

(порт задаётся переменной `PORT` в `.env`).

Префикс REST-ресурсов: `/api/categories`, `/api/exhibits`, `/api/news`, `/api/reviews`, `/api/visitors`. Эндпоинты с замком в Swagger требуют JWT; операции с `@RequireAdmin()` — роль администратора.

Дополнительно реализован **GraphQL** на `/graphql` (песочница Apollo в режиме разработки).

## Заключение

В ходе выполнения курсовой работы был проведён анализ деятельности виртуального музея технологий будущего, выделены участники процесса и доменные сущности (категории, экспонаты, новости, отзывы, посетители, пользователи системы). На основе анализа сформированы функциональные и нефункциональные требования к информационной системе.

Спроектированы системная архитектура (клиент — сервер NestJS — PostgreSQL — объектное хранилище), архитектура данных (ER-модель) и программная архитектура (модули NestJS по поддоменам). Выбран стек: TypeScript, NestJS, Prisma, PostgreSQL, JWT, REST и GraphQL, Swagger OpenAPI 3.0.

Реализованы серверная часть с REST API и MVC-интерфейсом на Handlebars, модуль аутентификации и авторизации с ролями пользователь и администратор, клиентские HTML-страницы музея. Документирование API выполнено средствами Swagger.

Таким образом, цель работы — разработка веб-приложения и пользовательского интерфейса информационной системы музея — достигнута. Разработанное приложение является результатом курсовой работы по дисциплине «Web-программирование».
